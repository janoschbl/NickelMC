# Explosion test fixtures

These files are generated by Java or captured from Minecraft. Do not edit them by hand.

## `java_block_pos_set/tests/openjdk25*.txt`

Output of `java_block_pos_set/tests/HashSetOracle.java`, which inserts `BlockPos` values into a real
`java.util.HashSet` and prints the bucket count, tree-bin count and iteration/tree-shape digests after
every insertion. `JavaBlockPosSet` is checked against it by `java_block_pos_set/tests.rs`.

Run `HashSetOracle` on OpenJDK 25 with Minecraft's server and library jars on the classpath
(`net.minecraft.core.BlockPos` must resolve) and `--add-opens java.base/java.util=ALL-UNNAMED`:

- `openjdk25.txt`: run with no program arguments.
- `openjdk25-sequential-identity.txt`: run with `--sequential-identities` and the VM options
  `-XX:+UnlockExperimentalVMOptions -XX:hashCode=3`, so `System.identityHashCode` increases monotonically
  and the tie-break order of equal-hash keys is reproducible.

## `tests/vanilla-tnt-order.txt`

Radius 4 TNT blast captured from vanilla (`iteration`, `callbacks`, `fuses`, `surviving-tnt` sections and
the `insertions-sha256` line). The inputs reproduced by `tests/gameplay.rs` are:

- Obsidian everywhere in `x, z ∈ [-4, 20]`, `y ∈ [52, 80]` except an air strip at `y ∈ [65, 67]` where
  `|x + z - 16| <= 1`.
- TNT blocks at `(6, 65, 9)`, `(10, 65, 5)` and `(8, 65, 7)`.
- Source: a primed TNT at `(8.5, 65, 8.5)`, explosion center `y` raised by `height * 0.0625`, radius 4,
  `LegacyRandom` seed 1 for the rays and the shuffle.

The vanilla harness that produced this file is not in the repository.

## `tests/creeper-blast-order.txt`

Output of `tests/BlastOracle.java`, a standalone source-derived oracle for 26.3
`ServerExplosion.calculateExplodedPositions` and `Util.shuffle`. This is not a capture of a running
Minecraft server. `tests/creeper.rs` builds the same mixed-resistance world and checks radius 3, 4,
and 6 blasts through both the sequential and cached paths, including block destruction.

Regenerate from the repository root with OpenJDK 25 and jq. Block resistances come from the existing
SteelExtractor output rather than a second handwritten registry:

```bash
mapfile -t blast_resistances < <(jq -r '.blocks[] | select(.name == "stone" or .name == "dirt" or .name == "glass" or .name == "water" or .name == "obsidian") | "\(.name)=\(.behavior_properties.explosionResistance)"' steel-registry/build_assets/blocks.json)
java steel-core/src/world/explosion/server/block_rays/tests/BlastOracle.java "${blast_resistances[@]}" > steel-core/src/world/explosion/server/block_rays/tests/creeper-blast-order.txt
```

`java steel-core/src/world/explosion/server/block_rays/tests/BlastOracle.java --loot` prints independent
`ApplyExplosionDecay` and `ExplosionCondition` expected counts: seed 1, 64 draws, 24 survivors at radius 3,
20 at radius 4. The Rust loot test injects the same legacy draws through a test-only adapter. Production
block-loot RNG selection is not seeded by this adapter and is not certified by that test.
